Description of the results to be achieved in Activity 1.4¶

In the subject SAR/SAZ they provided you with the code of a basic file service. The service client generated messages for the server according to a menu with the following options:

  1. List directory files

  2. Download a file

  3. Upload a file

  4. Delete a file

  5. Exit the service

Now we intend to convert the file service into a cloud service, such as Dropbox. The idea is that the client has a local copy of the directory and a backup of it on the server. In the simplest case, which is what we intend in this activity, the directory is not shared with other clients (that is, all updates arrive from the same client), so there are no consistency problems.

What we want is to hide the interaction with the server from the user. This will be completely automatic for the user, who performs his operations exclusively on his local directory. Thanks to the inotify native Linux notification service, the client can detect changes to a file and automatically communicate them to the server. It must be taken into account that now the query operations (list files and download a file) do not have to generate a request to the server, since the local directory has an exact copy of the client directory on the server. For this we will assume that initially the local and remote directories are empty.

For the implementation, the simplest thing is to keep the notification client and the file system client as independent. Both programs can run concurrently and communicate using standard input/output. The notification client will generate the menu commands that the file service client already knows how to interpret.
