A user complains¶

We are responsible for the computer science service of the university, and we provide users, students and professors, a network file service and a time service. We have received the following complain from a computer engineering student about the inconsistent operation of the file service version system:

This morning I was working on Linux on a program composed of two source files, a.c and b.c. At 9:30:00 (time of my computer) I have executed make to compile the application and obtained the files a.o, b.o and a.out (the executable file). When executing a.out, I have detected a rather silly error, so at 9:30:30 I have edited the a.c file to fix it, which took me just 15 seconds. I have immediately saved the file and executed make again. When I have executed a.out again I have observed with surprise that the error persists. It seems that the version system of the file service that you manage does not work properly, since it has not labeled the corrected version of a.c as newer than a.o, which has confused the make tool.

Checking the incidents of our server we have seen that at that time the time service has executed an operation to adjust the clock of that user’s computer, detecting a positive deviation (i.e., and advance) of 1 minute. Could this explain the problem?
