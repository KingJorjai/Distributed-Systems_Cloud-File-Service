Part 1. Distributed systems: from the network to the cloud¶

Years ago, the question where do you have such a document? had the answer: on my PC, and just in case I keep a copy on a pendrive/CD/floppy/… (the latter depends on the epoch we did the question). Later, computers and devices of all kinds and low cost proliferated, interconnected directly or through the Internet. One no longer only had a PC, but also a laptop and a mobile phone. And we had to take care that this document (or email, or note in the calendar), was available in its latest version wherever we needed it. Tools emerged that allowed to synchronize the versions of the document, but these were rather typical of computer scientists and geeks. In the subject Servicios y Aplicaciones en Red (SAR/SZA), which you would probably study last year, you studied examples that fit this scheme.

Today, the ideas about information support are different. We have the cloud to store our documents, messages, calendars, music or photographs. The question where do you have such a document? is now answered quite differently, perhaps: in my Dropbox storage or in my Google Drive storage. Maybe even the question is meaningless…

Clearly, Google Drive, Dropbox and other cloud services are making our lives easier, and we are probably not aware of the complexity behind the magic of the cloud. Within the scope of what we will call Distributed Systems, there are many concepts, technologies and models that have had to be developed so that today we can enjoy these services. As computer engineers we must be able to understand and manage them.

What do we need to learn to understand how one of these services is designed and built? Will we be able to build our own file service in the cloud?

The following activities are aimed at finding a positive answer to these questions.

Activity 1.1. The potential of distributed systems¶

Estimated dedication: 4 hours¶

Beyond the commercial products we use in everyday life, distributed systems are helping to solve problems that would be unapproachable with centralized systems. What are the characteristics and properties that allow them to face these problems successfully?

We will analyze a real case of application of distributed systems, such as information processing in the LHC (Large Hadron Collider). This example will serve to illustrate the properties of distributed systems and their fields of application.

What is there to be done¶

  1. The teacher will provide a copy of a paper written by J.M. Hernández and G. Merino: Una red global de computación para el LHC, Investigación y Ciencia, March 2014. Read it carefully (details about particle physics are only relevant to understand the magnitude of the problem). Write down the most important ideas.

  2. From a self-assessment test that the teacher will provide, analyze the extent to which you have understood the problem and the solution.

  3. In class we will solve the doubts. Also, the teacher will complete the spectrum of fields of application of distributed systems and outline the relevant properties of systems such as the one presented in the article. The Notes of Topic 1 (sections 1.2 and 1.3) will serve as a guide.

Results¶

The activity is evaluated in a subsequent test.

Activity 1.2. A network file system¶

Estimated dedication: 4 hours¶

The cloud is a concept that hides great complexity. It basically involves the abstraction of the distribution of hardware and software resources and the underlying network. But let’s go step by step. We are now in a position to consider the construction of a network file service. Obviously its properties will be much more limited than those of an ideal distributed system (a cloud file service), but we will already have a first form of resource distribution.

Note

In the subject SAR/SZA you could study the architecture and functionality of a network file system. This is a good basis to reflect on the properties of such systems.

What is there to be done¶

  1. Recover the material of the SAR/SZA subject, which will be a basis for developing the subject’s project. Start up the network file service of that subject (if you did not take it, talk to the Distributed Systems teacher to provide you with the code). Discuss in the group the characteristics of a basic network file service like this. Write down the basic ideas that summarize (a) the support it uses, primarily communications protocols, and (b) the functionality it provides.

  2. In class we will discuss some questions about the design of a distributed file system like this, its scope and its limitations. This type of service is one of the first distributed systems that were developed, back in the 1980s. The teacher will make a brief historical introduction based on the Notes of Topic 1 (Section 1.1). He will also introduce the specific properties that a network file service should meet. The Notes of Topic 4 will serve as the basis.

  3. Prepare a group report that reasonably collects (a) what properties of those defined for a distributed file system meets the service of the SAR/SZA subject, and (b) what properties it lacks in relation to a cloud system as defined in Activity 1.2.

Results¶

The report is evaluated with a weight of 2% of the total grade.

In addition, the activity is evaluated in a subsequent test.

Activity 1.3. The importance of rules¶

Estimated dedication: 2 hours¶

Applications and services like the one we are going to develop are only possible due to the general adoption of common specifications and protocols.

In this activity we will explore what standards, both at the level of networks and communications as well as the operating system, languages, etc., have been imposed to make a cloud file service a reality.

What is there to be done¶

  1. Taking as reference products such as Dropbox or Google Drive, and your experience with network services and applications, discuss in the group what standards do you think have been key in the development of distributed systems. Make a list and justify the reasons.

  2. The teacher will collect the proposals to discuss them in class and introduce some concepts about standards, which you can consult in the Notes of Topic 1 (sections 1.5, 1.6 and 1.7).

Results¶

The activity is evaluated in a subsequent test.

Activity 1.4. Our cloud file service¶

Estimated dedication: 4 hours¶

We are already able to start with the design of a file service in the cloud. Later we will adjust the specifications. An idea of the operation of the service that we intend is offered by repositories such as Dropbox or EHUbox. These services, in addition to a web interface, use clients that capture notifications from the local file system. The latter makes access to files backed up in the cloud completely transparent. The user performs his operations (create, read, modify or delete files) on the local system, and the client is responsible for managing the copy in the cloud consistently and reliably.

We will leave for later fault tolerance and consistency management (for shared files). Now we will focus on implementing some aspects of transparency property in the client.

What is there to be done¶

  1. Discuss in the group what mechanisms we should introduce in the implementation of our network file system to convert it into a cloud file system, so that it meets the properties that we have defined for distributed systems. Make a list of these mechanisms and give it to the teacher.

  2. In class we will discuss your contributions. We will now consider some of the mechanisms that we must introduce to achieve transparency in the client, and we will see what other aspects we will leave for later. In particular, the teacher will present the notifications interface of the file system in Linux, inotify, which we will test by downloading this C code to capture notifications.

  3. Now you must integrate the notification service into the client of the network file service. The goal is to get a client that is capable of transparently generating messages for the file server, so that it maintains an updated copy of the client’s directory, in the same style as a Dropbox type service. Previously, in class we will discuss how to do it with minimal programming effort. Here you can find a more detailed description of what is intended.

Results¶

You have to show the teacher the implementation and demonstrate how it works.

The result is evaluated with a weight of 3% of the total grade.
