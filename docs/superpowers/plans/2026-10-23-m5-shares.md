# M5 Implementation Plan — Shares, ACL, and Notifications

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Share files/directories between users with `ro`/`rw` ACLs, notify owners and grantees after committed changes, and update shared local copies without waiting for a restart.

**Architecture:** Add replicated `SHAR`/`UNSH` operations and a `SUBS`/`UPDT` notification hub on the primary. Clients map shared files under `shared/<owner>/<path>`, store `access`, and run a dedicated notification connection that enqueues remote updates into `SyncWorker`.

**Tech Stack:** Python 3.10+, `unittest`, TLS/mTLS, SQLite, sockets, `watchdog`, `trustme`, Docker Compose.

## Decisions

1. Owned files stay at the local root; shared files use `shared/<owner>/<path>`.
2. Owner has implicit `rw`; self-share is rejected; `anonimous` cannot be a grantee.
3. `ro` grantees cannot upload/delete. Local edits are preserved as a local conflict copy and the remote version is restored.
4. `rw` grantees can upload/delete and participate in normal conflict copies.
5. Directory shares use prefix matching via `access_for`.
6. Notifications are sent after commit to the owner and matching grantees, excluding the origin `client_id`.
7. `S`/`R` notifications tell a grantee to reconcile a newly added/revoked share.
8. Reconnect runs a full `SYNC`; revocations remove local shared copies.
